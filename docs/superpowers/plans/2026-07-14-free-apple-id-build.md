# Free Apple ID Build Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make this fork build, sign, and run on a free Apple ID ("Personal Team") by disabling the four entitlements that require paid Developer Program membership, while keeping every concession explicit and trivially reversible.

**Architecture:** Build-configuration change only — no application source code is touched. Four YAML files are edited. Paid-only lines are *commented out*, never deleted, each tagged with a `# FREE-ACCOUNT:` marker so `grep -rn "FREE-ACCOUNT" .` yields the exhaustive undo list. The NSE and ShareExtension targets are dropped from the build, which is safe because the app target already compiles `NSE/Sources` directly.

**Tech Stack:** XcodeGen (project generation from YAML), Xcode 26.6, xcodebuild, Git LFS.

**Spec:** `docs/superpowers/specs/2026-07-14-free-apple-id-build-design.md`

## Global Constraints

- **Never edit `.entitlements` files directly.** They are generated by XcodeGen from the `entitlements: properties:` block in each `target.yml`. Direct edits are overwritten on the next `xcodegen` run. All entitlement changes go in the YAML.
- **Comment out, never delete.** Every disabled line is preceded by a comment beginning exactly `# FREE-ACCOUNT:`.
- **No application source code changes.** This plan touches only `app.yml`, `project.yml`, `ElementX/SupportingFiles/target.yml`, and generated artifacts.
- **`xcodebuild` needs `DEVELOPER_DIR`.** This machine's `xcode-select` points at the Command Line Tools, so `xcodebuild` and `simctl` are unavailable by default. Every build command must be prefixed with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer`.
- **Generated files are tracked in git.** `ElementX.xcodeproj/project.pbxproj` and `ElementX/SupportingFiles/ElementX.entitlements` are committed to the repo even though XcodeGen produces them. After every `xcodegen` run, commit the regenerated output alongside the YAML change.
- **Branch:** all work happens on `free-apple-id-build`, which is based on `develop`.
- **`NSE/SupportingFiles/target.yml` and `ShareExtension/SupportingFiles/target.yml` are NOT edited.** Once un-included from `project.yml` they are inert. Leave them alone.

### Task 2: Drop the NSE and ShareExtension targets from the build

**Files:**
- Modify: `project.yml:63-64`
- Modify: `ElementX/SupportingFiles/target.yml:227-229`
- Regenerated (commit this): `ElementX.xcodeproj/project.pbxproj`

**Interfaces:**
- Consumes: Task 1's edited `target.yml`.
- Produces: an Xcode project with exactly one app target and no `.appex` products. Task 4's build depends on this.

Both extensions declare `com.apple.security.application-groups`, which a Personal Team cannot sign. The NSE is dead without push anyway, and the ShareExtension would write to a container the app can no longer read.

This is safe because `ElementX/SupportingFiles/target.yml` lists `../../NSE/Sources` among the **app target's** own `sources` (so unit tests can link NSE code). Removing the NSE *target* stops the `.appex` from being built and embedded, but the NSE source still compiles into the app and the tests still link.

`io.element.elementx` belongs to Element's team and cannot be claimed by another. `APP_GROUP_IDENTIFIER` is deliberately left as `group.io.element`: with the entitlement gone the value is inert, and leaving it keeps the diff minimal.

> **Consequence of the empty team — do not skip this.** `project.yml:55` defines
> `KEYCHAIN_ACCESS_GROUP_IDENTIFIER` as `$(DEVELOPMENT_TEAM).$(BASE_BUNDLE_IDENTIFIER)`.
> While `DEVELOPMENT_TEAM` is empty, that interpolates to `.com.khamitovdr.elementx` —
> a malformed keychain access group with a leading dot. This is harmless for **compiling**
> (which is all Task 4 verifies) but the app must **not** be expected to store credentials
> correctly until a real team ID is filled in. Setting the team ID fixes it automatically;
> no other file needs to change.

## Out of scope (human action required)

**Device builds.** They cannot be verified by an agent on this machine, because no code-signing identity exists. To unblock:

1. Xcode → Settings → Accounts → add the Apple ID. This creates the Personal Team.
2. Read the team ID:
   ```bash
   security find-certificate -c "Apple Development" -p \
     | openssl x509 -noout -subject | tr ',' '\n' | grep OU=
   ```
3. Paste it into `DEVELOPMENT_TEAM` in `app.yml`, run `xcodegen`, and build to a connected iPhone.

**Known constraint:** free-account provisioning profiles expire after seven days, after which the installed app refuses to launch until rebuilt from Xcode. No configuration can avoid this.

**Known risk:** if device signing rejects `keychain-access-groups`, the fallback is to strip that entitlement *and* remove the access group from `KeychainController` — a source change, and therefore a decision to bring back to the human rather than make silently.
